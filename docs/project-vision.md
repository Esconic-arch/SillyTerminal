# SillyTerminal 项目方向

## 已确认的目标

SillyTerminal 模拟一台可持续使用的“黑客电脑”。玩家通过终端、文件、编辑器和浏览器探索虚构网络，并逐步能够对预先设计的目标系统开展调查、连接、获取权限与其他互动。

这台电脑是一个持续存在的环境。文件编辑、软件状态和对目标系统造成的变化应有合理的持久化方式。用户没有将“重新开始”设为游戏的默认流程；正常退出和再次进入不应主动恢复初始状态。

真实感是第一优先级。“简易版”通过缩减功能范围实现；保留的行为、界面、内容及其相互关系仍应可信。先研究真实系统和一手资料，再选择一个可以完整实现的功能子集。

项目使用同一套源码支持 Windows 和 macOS 开发与运行，具体实测范围以各轮检查结果为准。

## 已确认的摄像头方向

- 下一台可连接的虚构设备选择家庭摄像头，先设计固定机位，不提供转头功能。
- 玩家明确要求拍照时，系统确定拍摄时刻的画面内容，再请求生成图片；连接设备和普通浏览不自动触发拍照。
- 未来接入 ComfyUI 生成摄像头图片。具体模型、工作流、部署位置及接口实现仍待确定，当前尚未接入。
- 已确认未来接入 DeepSeek，并拟用它将冻结的摄像头场景整理成图像提示词，再交给 ComfyUI 生成照片。具体模型、数据格式、工作流与失败处理仍待确定。

具体设备与拍照流程见 [固定摄像头设计草案](fixed-camera-design.md)，跨方向调用建议见 [拍照生成接口草案](ai-camera-interface.md)。其中标为建议的范围仍待确认，阅读或讨论草案不启动 API 接入或功能开发。

## 当前基础与后续方向

当前已有受限文件系统、终端命令、简易 Vim、纯文字浏览器和 mc 双栏文件管理器。文件编辑统一使用 Vim，原有 edit 命令已移除；mc 当前可以直接启动，通用软件包、安装与卸载机制尚未实现。现有伪域名主要映射到内置网页；这并不意味着已经实现通用的远程主机、网络服务或权限系统。现状以 README 与当前源码为准。

本地电脑增加文字控制台登录：当前只有 `guest` 账户，首次设置密码，以后每次启动验证后进入终端；`exit` / `logout` 返回登录页。账户校验与成功登录时间保存在独立的本地运行数据中，结束会话保留文件和其他状态。此处的本地登录不代表已经实现远程账户或文件权限。

后续方向是让这些功能连接到同一个可操作的虚构世界：网页中提供的信息能够对应到目标主机、服务或账户，系统操作会产生可观察的反馈，并影响相关文件、权限、日志或页面。

游戏内目标的运行状态与宿主电脑的真实文件、账户和系统状态需要明确区分。沿用隔离的运行数据与初始资源分离的方式，保持玩家数据不进入 Git。

用户已确认增加“软件与扩展系统”的长期分工，负责让部分后续能力通过发现、获取并安装软件或插件获得。软件的来源、安装与使用应形成可信的流程，并与网站、终端及目标系统相互对应。具体预装范围、包格式、安装命令和插件接口仍待讨论；建立分工不代表立即实现这些功能。

用户已明确，未来会接入 DeepSeek API，在需要时提供 AI 互动；也会接入 ComfyUI，在需要时生成图片。当前已实现服务配置、系统凭据保存和只读连接检查，见 [AI 服务配置](ai-service-configuration.md)；互动生成、图片工作流与组合任务尚未实现。AI 接入需要结合角色、世界信息、上下文、提示词预设或生成工作流进行适配；具体行为与内容需求仍待设计。用户已确认建立独立的“AI 接入与生成系统”长期分工，职责见 [ai.md](roles/ai.md)。

用户提出后续需要考虑“破限”或类似 SillyTavern 的预设处理，具体需求、预期效果与实现方式留待后续讨论；当前建立分工不启动相关设计、实施或验证。

## 尚待讨论和确定的方案

以下是用户提出的考虑或后续讨论方向，不是要求立即实现的功能清单：

- 虚构网络如何组织；家庭摄像头的可达方式、身份验证与服务范围；其他目标有哪些、各服务模拟到什么程度。
- 哪些工具初始提供，哪些工具需要玩家找到安装方法后获得；安装、卸载和依赖如何表现。
- 世界信息、日常内容和可利用线索如何设计，之后分别由哪些网站、文件、日志或人物呈现。
- DeepSeek 互动和 ComfyUI 图片生成的触发场景、模型职责、提示词预设、上下文与状态接口、图片工作流及结果保存方式；摄像头链路参考上述接口草案。

讨论 AI 接入时，应明确哪些内容是已经确认的世界事实、哪些是生成的表达，以及模型如何与程序可校验的操作结果衔接。职责初始化阶段不调用 API、索取密钥或增加依赖；实际接入按后续具体任务开展。

## 分工如何衔接

| 方向 | 主要负责 |
| --- | --- |
| 网页设计与内容 | 网站结构、文章、公告、人物对话及信息的页面呈现 |
| 终端功能与交互 | 命令、输入输出、工具使用方式、终端宿主和本地文件操作 |
| 浏览器功能 | 文档显示、网址导航、历史、收藏及其他浏览能力 |
| 虚构网络与目标系统 | 目标主机、服务、身份、权限、远程状态及其持久化 |
| 软件与扩展系统 | 可安装软件与插件、获取和安装、版本及安装状态、软件自身功能与配置 |
| AI 接入与生成系统 | DeepSeek 与 ComfyUI 接入、角色预设与上下文、生成任务、图片和会话结果保存 |
| 整体设计与整合 | 已确认决定的记录、跨模块协调和版本验证 |

例如将来设计远程连接时，终端方向处理命令入口和会话交互，网络方向处理目标、身份验证和系统状态；网页方向呈现合理的信息，浏览器方向负责显示和访问。具体接口根据当轮需求确定。

各方向的职责是长期范围。读取本文用于理解项目，不代表自动启动上述功能的开发。用户的具体请求和已确认决定优先；新决定应以明确状态记录在共享文档中。
