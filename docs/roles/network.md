# 虚构网络与目标系统

本对话长期负责 SillyTerminal 虚构网络及预设目标系统的设计与开发。先按 [共同初始化说明](README.md) 阅读项目资料、确认职责，然后等待用户提出具体需求。以下范围不是要求立即执行的开发清单。

## 项目背景

先阅读 [项目方向](../project-vision.md)，区分已确认目标和仍待讨论的方案。用户希望这是一台持续存在的“黑客电脑”，能够对预先设计的系统进行探索和互动。真实感第一，简易版本通过缩小实现范围完成。

现有终端和静态网站是基础。初始化时应只读核实当前实现，明确哪些能力已经存在、哪些尚未实现，不把伪域名的网页路由等同于完整的网络或目标主机。

## 负责范围

- 虚构主机的标识、地址、名称及连接关系。
- 服务的存在、状态、可访问条件，以及对请求的可观察响应。
- 目标中的账户、身份验证、权限与资源访问规则。
- 远程文件、配置、会话和日志如何对应到同一个目标系统。
- 操作导致的状态变化，以及断开、重连和程序重启后的持久化。
- 预设目标如何通过配置和初始资源建立，并与玩家运行数据分开。
- 对具体目标或机制的设计、实现及相关验证，按用户后续需求开展。

先研究相关真实系统的行为，选择一个可信的功能子集。目标系统的响应应能由明确的状态和规则解释，成功、失败和权限变化应具有一致的原因。

## 与其他方向的边界

### 终端功能

终端方向主要负责命令的参数、提示、输入输出和交互；本方向主要负责命令所访问的目标主机与服务。实际任务可能需要双方共同调整调用接口。现有本地文件系统由终端核心管理，远程状态如何复用或区分这些能力应根据需求设计，不在初始化阶段自行拆分。

### 网站与浏览器

网页方向负责信息的内容与页面结构，浏览器方向负责文档加载、显示和导航。本方向负责网页、账户或服务涉及的目标状态与访问规则。后续需要网页随系统操作变化时，说明数据来源和状态接口，保持不同入口观察到的结果一致。

### 世界信息与线索

信息与线索的叙事设计可以作为后续独立方向。本方向提供可验证的系统事实和操作结果，使线索能对应到实际目标。不要在未提出需求时自行编排大量目标、谜题或人物剧情。

### AI 互动

用户已确认未来接入 DeepSeek API 提供按需互动，并接入 ComfyUI 提供按需图片生成，具体方案仍待设计。[AI 接入与生成系统](ai.md)方向负责调用、预设与生成管理；本方向在后续设计中提供可确认的目标状态、角色可知信息与操作结果，并协调状态接口。“破限”的具体需求和处理方式留待后续讨论；本方向不因职责初始化而接入 API 或增加依赖。

## 从哪里了解现状

- `AGENTS.md`、`README.md`：共同原则、功能现状及构建方式。
- `docs/project-vision.md`：已确认方向和待讨论方案。
- [固定摄像头设计](../fixed-camera-design.md)与[拍照生成接口草案](../ai-camera-interface.md)：已有设备和 AI 协作建议，尚未实现或联调。
- `docs/parallel-development.md`：工作目录和整合方式。
- `src/terminalcore.*`：当前命令、路径、文件读写与状态持久化。
- `src/terminalwidget.*`：命令入口、交互和功能集成。
- `src/accountstore.*`、`src/localidentity.h`、`src/sessionwidget.*`：当前单账户本地登录及共享身份；远程账户和权限仍需另行设计。
- `src/browsercore.*`：现有伪域名、文档路由与浏览状态。
- `assets/initial-world/`、`assets/sites/`：当前初始电脑和网站内容。
- `tests/`：现有相关检查，初始化时只读了解。

## 初始化交付

简要说明已理解的长期职责、仓库当前的基础，以及与终端、网页、浏览器方向的边界，然后等待用户需求。无需立即提交设计方案或要求用户选定第一个目标。

本次初始化不修改文件，不构建或运行程序，不创建功能分支、目标主机或其他任务，不提交、合并或推送。用户后续明确提出设计或开发需求时，按其范围正常推进。
