# 长期分工对话说明

这些文档用于建立长期负责某一方向的对话。职责范围描述的是以后可以处理的工作，不是要求立即执行的任务清单。

## 选择一个方向

| 方向 | 对应文档 |
| --- | --- |
| 网页设计与内容 | [websites.md](websites.md) |
| 终端优化 | [terminal.md](terminal.md) |
| 浏览器功能 | [browser.md](browser.md) |
| 整体设计与整合 | [integration.md](integration.md) |

给新对话一句“请读取 `docs/roles/websites.md`，作为本对话的职责说明”即可指定网页方向。其他方向替换文件名。仅要求读取本说明时，先了解可选分工，不自行认领方向或开始开发。

## 初始化时做什么

1. 阅读用户指定的角色文档、本说明、根目录 `AGENTS.md`、`README.md` 和 `docs/parallel-development.md`。
2. 有必要时，只读查看职责相关的目录和源码，以了解现有实现。当前状态以仓库为准，不依赖其他对话的完整历史。
3. 简要确认本对话的职责、相关的已有实现和与其他方向的边界。
4. 确认后等待用户提出具体需求。不要自行挑选功能、生成开发计划或开展改造。

初始化不修改文件，不构建或运行程序，不创建分支、工作目录或新对话，不提交、合并或推送。无需为了确认职责而要求用户立即提供本轮目标。

## 后续怎样工作

用户以后可以在同一对话中讨论想法、比较方案、询问现状、要求检查问题，或提出具体开发任务。讨论与开发的范围以用户当前请求为准；已有明确授权时正常推进，不因初始化时的“等待需求”而再次要求确认。

保持长期职责连续。完成一轮工作后仍保留该方向，后续需求继续在本对话处理。开始新一轮时先了解当前仓库状态和已整合的变化，不要求初始化时改变任何 Git 状态。

职责边界用于协调，不机械禁止必要的跨模块修改。执行具体任务时保留其他任务的工作，说明涉及其他模块的接口、共同文件和验证结果。用户可以随时调整或重新指定分工。

项目共同原则以 `AGENTS.md` 为准。尤其是：真实感第一；简易版本通过缩减功能范围实现，保留的部分仍应可信。提交、合并和推送按当轮指令及既有授权执行；角色初始化本身不启动这些操作。
