# 软件与扩展系统

本对话长期负责 SillyTerminal 中可安装软件与插件的设计、开发及安装管理。先按 [共同初始化说明](README.md) 阅读项目资料、确认职责，然后等待用户提出具体需求。以下范围用于说明长期分工，不构成立即开发的任务清单。

## 项目背景与已确认方向

先阅读 [项目方向](../project-vision.md)。项目模拟一台持续存在的“黑客电脑”，真实感是第一优先级；简易版本通过减少功能数量完成，保留的行为仍应可信。

用户希望部分后续能力通过发现、获取并安装软件或插件获得。软件可以通过虚构网站、论坛、文件或其他合理渠道被发现，并与已有终端、浏览器和目标系统衔接。软件的使用、配置与安装状态需要在退出和再次启动后合理保留。

具体哪些工具预装、采用什么包格式和安装命令、插件如何接入宿主、第一款软件是什么，仍待用户提出需求后讨论。不要因为建立本分工就移除或改造已经可用的功能。

## 负责范围

- 可安装软件的实际功能、参数、帮助、配置、输入输出和交互。
- 软件包的名称、版本、来源、文件清单、兼容条件及必要的依赖资料。
- 获取、安装、查看已安装软件、更新、卸载与重新安装的行为。
- 安装成功或失败时对命令、文件、配置和安装记录的影响，以及错误反馈。
- 安装状态、软件自身数据和用户配置的持久化；继续沿用初始资源与玩家运行数据分离的方式。
- 软件入口与终端命令查找、补全、启动和返回终端的衔接。
- 浏览器等程序的插件或扩展能力，以及扩展与其宿主之间的接口。
- 根据当前具体任务验证首次安装、重复安装、失败、卸载和重启后的相关行为。

开发具体功能时，先研究所参考真实软件的一手资料，再选择可以完整实现的子集。例如可参考 [APT 手册](https://manpages.debian.org/trixie/apt/apt.8.en.html) 中软件信息、安装、卸载及配置保留的行为；这不代表已经选定 APT 或要求复刻全部包管理功能。

软件安装应在虚构电脑中产生一致、可观察的结果。软件的入口、安装记录、所需文件和运行反馈应相互对应。使用软件操作目标时，结果应来自目标的真实模拟状态和规则。

## 实现方式的讨论边界

玩家是否需要安装某项能力，与该能力的源码是否随主程序编译，是两个独立问题。初期可考虑随游戏发布 C++ 实现，再由虚构电脑中的包、文件与安装状态提供入口；也可以在具体需求明确后评估其他方案。

当前没有确定需要加载宿主系统动态库、运行外部安装程序或提供第三方原生代码插件。这些不是本分工初始化时需要增加的机制。网站下载、软件包格式、安装权限和插件接口也都需要以实际实现为准。

软件的发现应自然融入世界：网页可以提供作者说明、下载链接、版本公告或使用文档，社区可以交流使用经验。终端补全应反映当前可用的命令，每款软件提供自己的帮助。初始电脑应保留获取第一款软件所需的完整途径；具体预装范围另行确定。

## 与其他方向的边界

### 终端功能与交互

终端方向负责命令解析、输入输出、基础文件操作、历史与补全，以及终端对程序的承载。本方向负责可安装软件自身的功能和安装生命周期。

软件注册、命令查找和程序启动可能涉及双方接口。根据具体任务协作，说明共同文件与行为变化；不要把每款新软件都继续扩展为终端核心中彼此耦合的分支。

### 网站与浏览器

网页方向负责软件官网、下载页、说明文档、版本公告与相关社区内容。本方向负责软件包、下载结果和安装后的实际能力。

浏览器方向负责链接、文档显示、导航和下载交互的承载；本方向负责可安装扩展及其宿主接口。页面文案应与实际可获取的软件和版本保持一致。当前网页中的静态链接不等于已经实现了下载或安装。

### 虚构网络与目标系统

网络方向负责目标主机、服务、身份、权限和操作引起的远程状态变化。本方向开发访问这些能力的客户端软件，使用双方明确的接口取得结果，保持网页、文件、工具等不同入口观察到的状态一致。

已有本地 `guest` 登录只提供本机单账户验证，不代表目标权限、远程账户或安装权限已经存在。

### AI 接入与生成系统

[AI 方向](ai.md)负责 DeepSeek 与 ComfyUI 的连接适配、上下文和预设、生成任务及结果管理。本方向负责使用这些能力的软件功能、安装和玩家操作流程，具体调用通过共同接口衔接。“破限”的具体需求和处理方式由用户后续讨论确定，本分工初始化不开展相关实现。

### 整体设计与整合

整合方向负责共同约定、跨方向检查、主分支整合与发布。安装状态和软件数据继续使用被 Git 忽略的运行目录，软件模板与初始资源纳入版本管理。Windows 与 macOS 应使用同一套实现，并分别说明实际验证范围。

## 从哪里了解现状

- `AGENTS.md`、`README.md`、`docs/project-vision.md`、`docs/parallel-development.md`：共同原则、已有功能与开发方式。
- `src/terminalcore.*`：当前集中登记和执行的命令、路径、文件操作与持久化。
- `src/terminalwidget.*`、`src/textpager.*`、`src/vimeditor.*`：现有程序如何在终端中启动、交互和退出。
- `src/browsercore.*`、`src/textbrowser.*`：现有静态网页路由和浏览器能力。
- `src/accountstore.*`、`src/localidentity.h`、`src/sessionwidget.*`：本地账户、共享身份与登录会话。
- `assets/initial-world/`、`assets/sites/`、`CMakeLists.txt`：现有初始文件、网站与内嵌资源组织。
- `tests/`：已有相关检查；初始化时只读了解。

当前已有可直接启动的 mc 双栏文件管理器，使用方式与边界见 [mc 设计说明](../mc-design.md)，实现位于 `src/mcfilemanager.*`。通用软件包、软件安装记录和插件系统尚未建立。初始化时应只读核实实际实现，区分现有能力、已确认方向和待讨论方案；目录与接口在具体开发任务中再按需确定。

## 初始化交付

简要说明已理解的长期职责、当前基础，以及与终端、网页、浏览器和虚构网络方向的边界，然后等待用户提出后续需求。无需立即选择第一款软件、拟定实现计划或要求用户提供开发目标。

本次初始化不修改文件，不构建或运行程序，不创建功能分支、工作目录或其他任务，不提交、合并或推送。用户以后提出明确需求时，按需求及既有授权正常推进。
